### Simulation Test Cases

This testbench verifies the **1110 Mealy Sequence Detector** under four different scenarios.

#### 1. System Reset (0ns – 20ns)
* **Input Stream:** `0`
* **What happens:** The reset signal is active (`rst=1`). The system is forced to stay in the `idle` starting state and ignores all incoming data. 
* **Output (`det`):** `0`

#### 2. Normal Sequence Detection (30ns – 60ns)
* **Input Stream:** `1` → `1` → `1` → `0`
* **What happens:** The exact correct pattern is fed into the detector one bit at a time.
* **Output (`det`):** Spikes to **`1`** at exactly 60ns when the final `0` is received.

#### 3. Broken Sequence (70ns – 90ns)
* **Input Stream:** `1` → `1` → `0`
* **What happens:** The pattern starts correctly but breaks early (a `0` arrives instead of a `1`). The machine resets itself back to the `idle` state.
* **Output (`det`):** Stays `0`.

#### 4. Extra Preamble Bits (100ns – 140ns)
* **Input Stream:** `1` → `1` → `1` → `1` → `0`
* **What happens:** Four `1`s are sent in a row. The machine correctly ignores the extra first `1`, remembers the last three `1`s, and finishes the sequence successfully when the `0` arrives.
* **Output (`det`):** Spikes to **`1`** at exactly 140ns.

---
**💡 A Note on the Output Waveform:** Because this is a **Mealy Machine**, the `det` output triggers instantly the moment the final `0` input arrives, without waiting for the next clock cycle. When the next clock cycle does hit a moment later, the machine resets. This is why successful detections appear as quick "half-clock" pulses on the waveform graph
